# DeiLaw 0.3.5rc11 — текущее состояние защитных мер

## Применено к боевому Supabase

- `deilaw-report-attachments` **v4**, JWT + проверка владельца, приватный bucket, 10 MiB, подписи PNG/JPG/WEBP, запрет новых ZIP, `X-Content-Type-Options: nosniff`, обязательный антивирусный verdict + SHA-256. **Новые вложения отклоняются (fail-closed), если AV сервер ещё не настроен.** Ранее существовавшие файлы не удалены.
- БД: атомарный триггер ограничения количества вложений до 5 на репорт; протестирован с откатом изменений.
- Ограничение на 10 репортов, 100 сообщений, 10 предложений за 24 часа на аккаунт. JWT/RLS/Discord ownership действуют.
- Cloud AI v9; JWT, лимит по user/global, не логирует сырые upstream error/response, тайм-аут внешнего запроса.

## Подготовлено в исходниках, но не развёрнуто за пределами Supabase

- `build_release.ps1` подписывает Authenticode основной `DeiLaw.exe` **и** Inno Setup installer; проверяет обе подписи перед выпуском подписанного Ed25519-манифеста.
- Зашифрованные сценарии backup `security/backup_encrypted.py`, `security/backup_storage_encrypted.py` и read-only `security/backup_restore_check.py` без plaintext staging. **Фактический независимый бэкап ещё не выполнялся**, потому что нет подключения к резервной машине, импортированного GPG public key и доступа к секрету DB/Storage. Для полного восстановления нужна отдельная staging-проверка.
- Пример ClamAV `security/av_gateway/clamav_gateway.py` со строгим HTTPS-proxy requirement. **Сканирующий сервис ещё не запущен и не тестировался через внешний HTTPS URL.** Без него загрузки остаются заблокированными.
- 77 внутренних автотестов в среде исходников; это не Windows E2E и не аудит третьей стороны.

## Блокирующие условия

1. Supabase Auth: создать Cloudflare Turnstile/hCaptcha site и secret; внедрить desktop challenge и протестировать парольный/гостевой/Discord вход **до** включения обязательной CAPTCHA. Соответствующий настройки Supabase Auth через доступный коннектор изменить не удалось.
2. Supabase Auth: Leaked Password Protection (доступность Pro+) и MFA для администратора — пока не включены, предупреждение Advisor сохраняется.
3. CA-issued Authenticode certificate (желательно HSM) + offline Ed25519 key; сейчас в исходниках `UPDATE_ED25519_PUBLIC_KEY_B64` пустой, следовательно автоустановка безопасно заблокирована.
4. Внешний независимый pg_dump + экспорт байтов из Storage с GPG и тестом восстановления — нет настроенного хранилища/ключей.
5. Работающий отдельный ClamAV service + корректные `DEILAW_AV_SCAN_URL`, `DEILAW_AV_TOKEN`, тест clean и malware reject. Текущий fail-closed временно блокирует вложения.
6. Независимый пентест Windows / Supabase / GitHub release chain — не проведён.
7. У Qt 6.12.0 есть публично известные CVE в отдельных подсистемах (в т.ч. QCbor/Qt5Compat), а доступной PyQt6-Qt6 6.12.1 на PyPI на дату проверки ещё нет. Проверить фактическую достижимость уязвимых API, затем обновить runtime при появлении исправленной сборки.

**Вывод:** часть рисков технически снижена, но невозможно подтвердить «100% закрытие всех уязвимостей». Нет права объявлять релиз сертифицированным, пока блокирующие условия не выполнены.
