# Шлюз антивирусной проверки DeiLaw

Это **пример реализации**, а не уже запущенный сервер. Для активации требуется изолированная Linux-машина / контейнер с `clamscan`, регулярными обновлениями баз через `freshclam`, достаточной памятью, HTTPS-терминацией, защищённой сетью и мониторингом. Используйте выделенный сервис, не Supabase API.

1. Создайте криптографически стойкий токен (например `openssl rand -hex 32`) и положите его **только** в `DEILAW_AV_SERVER_TOKEN` сервиса. Не коммитьте и не присылайте его в чат.
2. Запустите `clamav_gateway.py` от ограниченного пользователя, слушающего только localhost. Откройте `/scan` через HTTPS-прокси, доступный из Supabase Edge. Требуются строгие правила IP/размеров/таймаутов, логирование без персональных данных и мониторинг ошибок.
3. Установите в **Supabase Edge Function Secrets** `DEILAW_AV_SCAN_URL=https://your-owned-host/scan` и `DEILAW_AV_TOKEN=<тот же токен>`. Проверяйте, что реальные бинарные файлы принимаются при `verdict=clean`, а EICAR-тестовый файл (только из официального источника) блокируется.
4. При отсутствии секрета, истечении тайм-аута или ошибке сервиса загрузки остаются заблокированными. Это умышленно: **нет сканирования — нет новых вложений**. Старые вложения пока остаются доступными и не пересканированы.

Ответ шлюза (с обязательным сравнением SHA-256 на стороне Supabase): `{"verdict":"clean","sha256":"lowercase_hex_hash"}`. Для вредоносного файла — `verdict=infected`. Никакие пользовательские файлы не должны загружаться на непроверенные сторонние API без согласования приватности.


## Развёртывание на своём VPS с Docker Compose

Эта конфигурация не зависит от внешнего хостинг-плагина. Вам нужен
**свой Linux VPS и домен** с A/AAAA-записью на VPS. Храните секреты только на
вашем сервере, не присылайте их в чат.

1. Установите Docker Engine и Docker Compose plugin по официальной документации.
2. Скопируйте каталог `security/av_gateway` на VPS. В том же каталоге скопируйте `.env.example` в `.env` и задайте `DEILAW_AV_DOMAIN` и новый токен, созданный `openssl rand -hex 32`.
3. Ограничьте права файла `.env`: `chmod 600 .env` и убедитесь, что он не входит в Git или архив публичного релиза.
4. Запустите `docker compose up --build -d`. Опубликуйте наружу только порты HTTPS (443) и HTTP (80 для ACME), **не** 10000. Caddy получает сертификат автоматически при работающем DNS.
5. Дождитесь актуальных сигнатур: `curl -f https://<ваш-домен>/health` должен вернуть `{"ready":true}`. Проверяйте журналы и обновления ClamAV; наличие HTTP 200 само по себе не подтверждает обнаружение вирусов.
6. В Supabase → Edge Functions → Secrets создайте `DEILAW_AV_SCAN_URL=https://<ваш-домен>/scan` и `DEILAW_AV_TOKEN=<тот же секрет>`. Не добавляйте эти переменные в клиентские исходники.
7. На **тестовом** репорте проверьте чистый PNG и EICAR-тестовый образец из официального источника. Отдельно проверьте недоступность сервиса (upload должен вернуть 503). Если проверка не пройдена — не принимайте файлы.

Для сканирующего сервиса обеспечьте достаточную RAM (от 3 ГиБ для контейнера),
мониторинг `/health`, обновление ОС/контейнеров и ограничения доступа. Caddy
публикует только `/scan` и `/health`, а сам scanner недоступен через host port.
Версии базовых контейнеров нужно дополнительно зафиксировать по проверенным
image digest перед публичным выпуском.
