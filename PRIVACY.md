# Privacy / Конфиденциальность
Этот файл описывает данные, с которыми работает актуальный исходный код DeiLaw. Он не заменяет юридическую политику конфиденциальности сервиса.

## Локальные данные

DeiLaw может хранить на компьютере пользователя локальную базу законодательства, настройки, историю поиска, историю обновлений, логи, данные памятки, черновики/историю RP-помощника, резервные копии и идентификатор установки. Эти файлы относятся к runtime-данным и исключены из Git.

## Community identity

При первом использовании Community-функций клиент создаёт случайные `installation_id` и `installation_secret` в локальном runtime-файле. На Windows клиент читает MachineGuid локально и использует его только как вход для salted SHA-256. В сетевые запросы передаётся производный hash/device ID, а не исходный MachineGuid.

На Windows идентификатор установки и секрет сохраняются в зашифрованном DPAPI-файле. При запуске старый открытый файл мигрирует без смены идентификатора. Новые резервные копии не содержат секретов и токенов, однако прежние копии могут содержать секрет в открытом виде.

## Cloud AI

Согласно `ai_core/cloud.py`, в Cloud AI отправляются:

- текущий вопрос/RP-ситуация (до 5000 символов);
- до 6 последних сообщений диалога, каждое ограничивается клиентом;
- режим запроса и точные ссылки на статьи при наличии;
- версия DeiLaw;
- JWT Supabase Auth для авторизации Cloud AI. На сервере он проверяется перед расходованием AI-квоты.

Поиск по полной серверной базе законов выполняется в Supabase. OpenAI API вызывается backend-функцией, а не desktop-клиентом.

Описанные меры защиты Cloud AI пока подготовлены в исходниках. Применение к работающему серверу требует отдельной миграции (docs/SECURITY_ROLLOUT.md).

## Отзывы, репорты и предложения

Данные, которые пользователь сам отправляет через Community-разделы (текст отзыва, репорта, сообщения, предложения и разрешённые вложения), передаются серверу DeiLaw для соответствующей функции.

## Что не должно публиковаться в Git

Локальные `.env`, токены, пароли, пользовательские базы, identity-файлы, логи, вложения и резервные копии исключены правилами `.gitignore`.


## Фоновые подключения — добровольное согласие (кандидат для SignPath)

Новый NSIS-установщик показывает текст `installer/PRIVACY_INSTALL.txt` перед
установкой и предлагает **необязательные, изначально выключенные** функции:

- проверка новых версий через GitHub (периодически, до входа в программу);
- автоматическая синхронизация игровой базы законов с ресурсами RMRP;
- фоновая проверка ответов на репорты в Supabase.

Пользователь может включать/выключать эти три опции позже в настройках.
При повторной установке существующий `data/settings.json` сохраняется:
выбор текущего пользователя не перезаписывается. Старые установки могли
ранее иметь автообновления включёнными — необходимо просмотреть настройки.

**Действия, инициированные пользователем**, такие как вход через Discord,
гостевая сессия Supabase, отправка репорта, использование Cloud AI, ручная
проверка обновлений или запрос на загрузку законов, выполняют соответствующие
сетевые запросы даже при выключенных фоновых проверках. Чтобы исключить
необязательные передачи, не используйте соответствующие облачные функции.
Для использования текущего клиентского интерфейса требуется выбор гостевой
или Discord-сессии, то есть полностью автономный старт без сетевого входа
пока не реализован. Этот момент дополнительно требует оценки при проверке
условий SignPath и не должен скрываться при подаче заявки.
