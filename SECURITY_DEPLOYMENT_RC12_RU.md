# DeiLaw 0.3.5rc12 — обязательные действия для полного безопасного запуска

Дата проверки: 12.11.2026. Это инструкция к *подготовленной* инфраструктуре, **не сертификат безопасности**.

## Сначала — текущее состояние рабочего проекта

- Supabase `ntizjwncrbokebjsfwgu`: JWT/RLS, Discord-привязка, лимиты сообщества и авто-модерация работают. Функции `deilaw-ai` v9, `deilaw-report-attachments` v4 и `deilaw-law-sync` v1 требуют JWT.
- `bug-report-attachments` является приватным bucket; при отсутствии антивирусного сервера новые файлы **не принимаются** (HTTP 503). Два ранее сохранённых объекта не удалены и не пересканированы.
- Действующее логическое резервирование внутри базы (схемы `deilaw_rollback_*`) **не заменяет** независимую резервную копию.
- Проверка проекта Supabase указывает на включённую анонимную авторизацию, намеренно привилегированную функцию `deilaw_claim_legacy_ownership` и не включённую защиту от утёкших паролей.
- Поддержка CAPTCHA добавлена в исходники 0.3.5rc12/Support Center 0.2.5, но публичный sitekey и секрет Supabase **не настроены**. Рабочая обязательная CAPTCHA **ещё не включена**.
- Нельзя публиковать неподписанный EXE или автоматически запускать непроверенный установщик.

## 1. CAPTCHA — включать только в правильном порядке

1. Создайте Turnstile widget в Cloudflare для доверенного домена. **Для production рекомендуется собственная HTTPS-страница проверки**, а не whitelist `localhost`/`127.0.0.1` (встроенный localhost-flow предназначен для тестирования и контролируемого выпуска, поскольку снижает привязку токена к домену).
2. Публичный *Sitekey* введите в `captcha_config.py` (`TURNSTILE_PUBLIC_SITEKEY_FOR_RELEASE`) и в `config.py` админки; **Secret key только в Supabase Auth**, никогда в EXE/архиве/чате.
3. Соберите тестовый DeiLaw и Support Center и проверьте создание гостевой сессии, вход в Support Center по email/паролю и Discord OAuth на **тестовом** проекте.
4. В Supabase → Authentication → Bot and Abuse Protection включите Turnstile и сохраните Secret key. Проверяйте, что запрос без CAPTCHA не проходит, а с настоящим токеном проходит.
5. Только после теста включайте на боевом Supabase и выпускайте клиент. Если Windows-сборки у пользователей устарели, сначала распространите поддерживающую версию — иначе возможна блокировка входа.
6. Поток браузерной Discord OAuth-провайдер авторизует через Discord; его CAPTCHA-поведение зависит от Supabase Auth и схемы OAuth. Проверьте отдельно, не полагайтесь на тест парольного входа.

Документация: https://supabase.com/docs/guides/auth/auth-captcha и https://developers.cloudflare.com/turnstile/

## 2. Защита паролей / админская учётная запись

- Supabase → Authentication → Security and Protection / Password Security: включите Leaked Password Protection (если план Supabase позволяет), длину не меньше 12, запрет слабых паролей.
- Включите MFA для администраторов после того, как в Support Center появится *проверенный* MFA flow, иначе можно потерять доступ. Сам по себе текущий парольный логин не подтверждает поддержку MFA.
- После изменения настроек проверьте новый вход, обновление токена, блокировку украденного пароля, RLS проверки администратора.
- В Supabase Security Advisor предупреждение `auth_leaked_password_protection` должно исчезнуть. Не отключайте просто ради скрытия предупреждений гостевой режим, если он нужен приложению.

Документация: https://supabase.com/docs/guides/auth/password-security

## 3. ClamAV — без облачного хостинг-плагина

- Выберите собственный Linux VPS и домен; установите Docker и Docker Compose. Конфигурация в `security/av_gateway/compose.yaml`, `Caddyfile`, `.env.example`.
- Скопируйте только `security/av_gateway` на VPS; новый приватный токен храните в `.env` (600), не включайте в Git. `docker compose up --build -d` после настройки DNS.
- Дождитесь `GET https://<домен>/health` с `{"ready":true}`. Проверьте ответ на чистый файл и на EICAR; остановите scanner и проверьте HTTP 503.
- В Supabase Edge Function Secrets задайте `DEILAW_AV_SCAN_URL=https://<домен>/scan`, `DEILAW_AV_TOKEN` с тем же секретом. Никогда не копируйте его в клиент.
- Только после реальной проверки новой загрузки отметьте антивирус «работает». До этого **вложения останутся заблокированы**; это осознанно безопасный режим.
- Ограничьте доступ к VPS, обновляйте OS/ClamAV, настраивайте мониторинг ошибок; старые 2 объекта нужно оценить отдельно.

## 4. Независимое резервирование и восстановление

- Нужны компьютер/сервер **вне Supabase**, `pg_dump`, `pg_restore`, `gpg`, `requests`, доступ к базе и Storage API (секреты только в окружении резервной машины).
- Создайте **свою** OpenPGP-пару ключей на доверенной машине, офлайн храните приватный ключ. Для скриптов используйте только *отпечаток публичного ключа*. Без пользовательского приватного ключа я не могу создать восстанавливаемый для вас зашифрованный бэкап.
- Выполните `python security/backup_encrypted.py --recipient <FINGERPRINT> --destination <OFFSITE_DIR>` для PG и `python security/backup_storage_encrypted.py --recipient <FINGERPRINT> --destination <OFFSITE_DIR> --bucket bug-report-attachments` для Storage.
- Скрипты стримят данные через GPG и не создают временный расшифрованный дамп. Ключ service_role для Storage только на backup host; не коммитьте `.env`.
- Проверьте SHA256, расшифровку и чтение dump через `security/backup_restore_check.py`; затем обязательно отработайте восстановление в **отдельном тестовом окружении**, не в prod. Настройте расписание и мониторинг отказов.
- Храните минимум одну копию вне провайдера и проверьте поведение при потере доступа к Supabase. Нет завершённого теста восстановления — бэкап не считается подтверждённым.

## 5. Подпись выпуска и безопасные обновления

- Получите сертификат подписи Windows от доверенного центра и настройте защищённое хранилище ключа, а также **свой** Ed25519 ключ, приватный файл которого никогда не публикуется.
- Закрепите публичный Ed25519 ключ в `update_trust.py`, а в `DEILAW_AUTHENTICODE_THUMBPRINT` — отпечаток действующего сертификата. Приватный Ed25519 путь — `DEILAW_UPDATE_SIGNING_KEY`.
- На Windows с SignTool и Inno Setup запустите `build_release.bat`. Сценарий проверит подписи `DeiLaw.exe` и установщика, SHA-256, затем подпишет манифест обновления.
- Проведите тест: настоящий релиз проходит; изменённый `.exe`/манифест/хэш отклоняется; ошибка подписи блокирует запуск установщика. Исходники из ZIP нельзя объявлять «подписанным релизом».

Документация: https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool

- До стороннего отчёта, проверок Windows и подтверждения состояния зависимостей (включая исправления Qt) **официальный релиз не считается сертифицированным**.
