# DeiLaw — обязательный фирменный стиль каждого выпуска

Каждая версия DeiLaw (обычная, тестовая и для разработчика) должна сохранять следующие возможности. Изменять дизайн допускается только осознанно; **беззвучная** замена на стандартные звуки Windows или пропажа фирменной иконки — регрессия.

- **Приложение:** фирменные темы и визуальные эффекты из `ui/main_window.py` (включая тёмный/светлый режим).
- **Иконка:** `assets/icons/icon.ico` внутри сборки, `installer/assets/deilaw_installer.ico` для Windows EXE и значка NSIS; иконка должна присутствовать в окне, Alt+Tab, панели задач, Start Menu и ярлыках.
- **Звуки приложения:** `assets/sounds/click.wav`, `button.wav`, `toggle.wav`, `save.wav`, `memo_open.wav`, `memo_close.wav`, `law_update_complete.wav`, `ai_complete.wav`, `report_reply.wav`. Сохранить индивидуальное отключение звуков настройками.
- **Оформление установщика:** собственные изображения `installer/assets/pages/` и фирменный графический стиль в NSIS. При сборке из PNG автоматически подготавливаются MUI bitmap-фоны.
- **Звуки установщика:** `installer_start.wav`, `installer_page.wav`, `installer_finish.wav` в `installer/assets/sounds`. Применяются при открытии, переходе и завершении мастера без запуска в тихом режиме.
- **Обязательные проверки:** `python -m unittest discover -s tests -q`; `tests/test_branding_release_contract.py` проверяет все обязательные элементы. Windows CI должен собирать установщик и проверить установку/удаление. Для оценки фактического внешнего вида и звука требуется отдельная ручная проверка в Windows перед выпуском.

**Происхождение звуков:** восемь оригинальных WAV-файлов интерфейса дословно восстановлены из официального установщика DeiLaw v0.3.0 (одинаковые SHA256 в установщиках v0.2.2 и v0.2.0). Оригинальный файл report_reply.wav сохранён. Три фирменных звука установщика отдельно созданы для версии с NSIS: оригинальные installer-WAV не найдены в установленных файлах старых версий.

**Два вида исходников:** главный `main` — чистый GPL-исходный код без BAT и служебных файлов разработчика; отдельная ветка `development` — рабочая копия тех же исходников с `run.bat` и локальными инструментами для разработки. BAT разработчика никогда не включаются в пользовательские бинарные выпуски и GPL-архив чистых исходников. Разработческая ветка не должна содержать настоящие API-ключи, пароли, личные данные или чужие защищённые материалы.

**Отдельный вопрос:** перед публичной раздачей EXE требуются соблюдение лицензий Qt/LGPL, проверка автоматического перехода 0.3.0 → 0.3.1 и цифровая подпись. Фирменный стиль не заменяет эти условия.
