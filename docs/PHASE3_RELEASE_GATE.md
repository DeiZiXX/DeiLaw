У Microsoft-библиотек может быть статус GPL System Libraries, что SignPath допускает; необходимо подтвердить это для **каждого** реально распространяемого файла. Не удалять библиотеки без совместимых замен и Windows regression tests.

## Что добавлено на третьем этапе

1. `scripts/classify_native_components.py`: матрица реальных native EXE/DLL/PYD в `release/component_review.json` с обязательными вопросами о правообладателях и лицензировании.
2. `scripts/test_nsis_install.ps1`: изолированный CI smoke-тест silent installation, исходного opt-out для трёх фоновых сетевых опций, повторной установки без изменения `data`, silent uninstall и сохранения пользовательских файлов. Тест использует новую временную папку runner и **не должен выполняться в пользовательской установленной копии**.
3. Windows unsigned CI прикладывает дополнительный JSON и выполняет smoke-тест после сборки.
4. Релизный SignPath CI проверяет неподписанный setup до подачи его на подпись. Это дополняет обязательные ручные проверки и не заменяет их.
5. Регрессионные тесты классификации и fail-closed поведения.

Для проверки правообладателем без публикации персональных документов подготовлен [OWNER_RIGHTS_REVIEW.md](OWNER_RIGHTS_REVIEW.md) — все поля оставлены **неподтверждёнными**.

## План интерактивной проверки владельцем на Windows

1. Сделать резервную копию `data/` действующего DeiLaw и зафиксировать её SHA-256 (без отправки ключей/секретов). Тест проводить на отдельной Windows VM или тестовой учётной записи, **не поверх рабочего DeiLaw**.
2. Запустить **неподписанный тестовый NSIS setup** из успешного CI. Проверить русскую кодировку, тексты GPL и конфиденциальности, доступность всех трёх выборов сетевых функций.
3. При отключённых опциях установить, запустить GUI, проверить локальную работу и отсутствие неожиданных фоновых соединений в среде с сетевым мониторингом.
4. Повторно установить в ту же тестовую папку; убедиться, что настройки/репорты/локальные данные не изменены.
5. Удалить программу; убедиться, что EXE и notices удалены, `data/` осталась. Протестировать Inno → NSIS отдельно с копией личных данных, без автоматического затирания.
6. Проверить запуск с заменёнными совместимыми Qt LGPL-библиотеками в тестовой VM и подготовить понятную инструкцию для пользователей, если LGPL требует этого.
7. После всех исправлений поставить отметки и прикрепить доказательства в PR, **только тогда** обсуждать merge и GPL release.
