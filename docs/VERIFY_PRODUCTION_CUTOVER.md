# DeiLaw — проверка защиты на рабочем сервере (12.11.2026)

В рабочем проекте Supabase `ntizjwncrbokebjsfwgu` применён переход на `owner_uid` / `auth.uid()` и обновлена Edge Function `deilaw-report-attachments` до v2 (`verify_jwt=true`). Следующие шаги проверяются в Windows-сборке v0.3.5rc7, а не при запуске миграций повторно.

## Что уже проверено на сервере

- Отзывы: 3 всего / 3 опубликованы. Репорты: 4; сообщений: 12; законов: 3318.
- У четырёх таблиц сообщества есть `owner_uid`.
- Старых RLS-политик, использующих `request.headers`, не осталось.
- Прямое чтение столбца `installation_secret_hash` запрещено ролям `anon` и `authenticated`.
- Публичные отзывы доступны через `deilaw_public_reviews` с `security_invoker=true`; доступ к опубликованным отзывам под ролью `anon` проверен.
- Без JWT роль `authenticated` не видит репорты.
- Внутренняя точка отката `deilaw_rollback_20261112` присутствует, но не заменяет внешнюю резервную копию.
- Проверка исходников: 40 тестов. Это не результат E2E-тестирования Windows-приложения.

## Ручная проверка Windows (ещё не выполнена)

1. Запустить ранее собранный `DeiLaw.exe` 0.3.5rc7 и войти через Discord. Запустить повторно: запрос входа не должен повторяться.
2. Проверить «Отзывы»: три ранее опубликованных отзыва видны; новый отзыв после отправки должен ожидать одобрения.
3. Открыть «Мои репорты»: если установка создавала старые репорты, одноразовая миграция прав по её секрету должна связать их с текущим аккаунтом. Не удалять папку `data` и защищённый файл учётных данных.
4. Создать новый тестовый репорт, добавить одно небольшое вложение, открыть переписку. Проверить получение и скачивание вложения через JWT.
5. Переключиться на другой Discord-аккаунт/гостя: прежние приватные репорты и переписка не должны быть доступны новому аккаунту.
6. Проверить запросы Cloud AI к реальным статьям; зафиксировать любые 401/403/429/500 сообщения без публикации токенов и личных логов.

## Оставшиеся риски

- Нужна внешняя резервная копия БД и настроек Auth: текущий откат внутри того же Supabase-проекта.
- Supabase предупреждает о временном RPC `deilaw_claim_legacy_ownership` с `SECURITY DEFINER`; доступ есть только у подтверждённого аккаунта и требует прежний случайный секрет установки. После миграции старых записей RPC следует удалить.
- Не настроены CAPTCHA/предупреждения о расходах OpenAI и защита от скомпрометированных паролей; проверка анонимной авторизации требует отдельной оценки риска.
- Автообновление не должно устанавливаться без подлинной подписи Ed25519 и Authenticode. Готового подписанного Windows-установщика нет.
- Нужен повторный независимый аудит и интеграционные тесты всех ролей.

**Не запускать повторно `SUPABASE_SETUP.sql` и не применять `SUPABASE_SECURITY_HARDENING.sql` к уже обновлённому рабочему проекту.**
