# DeiLaw — этап 2 GPL / SignPath: технические результаты и условия выпуска

Дата: 18.11.2026. Рабочая ветка: `prepare/gpl3-signpath-readiness-20261112`. PR: https://github.com/DeiZiXX/DeiLaw/pull/1

**Статус: подготовка в draft PR. Не объединять с `main`, не публиковать бинарный релиз и не запрашивать подпись до выполнения оставшихся проверок.** В `main` по-прежнему `All rights reserved`. В *публичной* ветке PR уже находится текст GPLv3 для тех материалов, на лицензирование которых у автора есть права; наличие текста не подтверждает права на все элементы проекта.

## Выполненные технические изменения

- `scripts/review_windows_bundle.py`: анализ собранной папки `dist/DeiLaw`, сверка SHA-256 каждого реально сохранённого файла лицензии с `THIRD_PARTY_LICENSES/license_manifest.json`, выявление пропусков и каталога EXE/DLL/PYD. Проверка завершается ошибкой, если отсутствует манифест/EXE или нарушена целостность уведомлений. **Это доказательства целостности, не юридическая сертификация и не runtime SBOM.**
- `scripts/build_signpath_candidate.ps1`: выпускает `release/license_evidence.json` вместе с `build_inventory.json`, прекращает выпуск кандидата при ошибке сверки.
- Windows CI загружает вместе с кандидатом `license_evidence.json` и исходный `license_manifest.json` для ручной оценки отсутствующих лицензий.
- `installer/DeiLaw.nsi`: при деинсталляции удаляет служебный `THIRD_PARTY_LICENSES`, но **не удаляет персональные `data/`**. Интерактивный тест на Windows остаётся необходим.
- `build_release.ps1`: принудительно задаёт UTF-8 при компиляции NSIS, как в тестовой сборке.
- `signpath-release.yml`: требует от запускающего человека подтверждения проверки кода, медиа и зависимостей **для точного SHA коммита**; запускает сверку уведомлений до запроса подписи и прикладывает её результаты к артефакту. Подписание по-прежнему требует защищённой среды, SignPath-проекта и действующих разрешений.
- Добавлены unit-тесты отсутствующего манифеста, изменённого LICENSE, отсутствующего EXE и явной отметки о необходимости человеческого аудита.

## Что остаётся блокирующим

1. **Юридическая проверка:** владелец должен доказуемо подтвердить право на GPL для всего собственного Python/SQL/TS-кода, вклады соавторов и происхождение 12 медиафайлов. Аудит не вправе присваивать лицензии третьих лиц.
2. **Реальные лицензии сборки:** изучить новые `release/license_evidence.json` и `THIRD_PARTY_LICENSES/license_manifest.json`; получить недостающие полные лицензии/нотисы Qt DLL и plugins, OpenSSL, CPython, VC Runtime и других распространяемых компонентов. Проверить LGPL-права на замену Qt DLL и соответствующий исходный код.
3. **Тест Windows на живой установке:** страницы GPL/приватности, opt-in, сохранение настроек и `data/`, запуск и деинсталляция; переход Inno → NSIS проверять только с резервной копией.
4. **Privacy и online-зависимости:** проверить все реальные сетевые запросы при новой установке и отсутствие скрытой обязательной передачи данных при запуске. Наличие переключателей в коде — не свидетельство соответствия.
5. **Защита выпуска и SignPath:** 2FA/MFA, branch protection, protected environment и reviewers, согласование сторонних компонентов с SignPath, approved Foundation account/project и trusted build origin. Токены и офлайн Ed25519 приватный ключ не коммитить. Публичный ключ в `update_trust.py` до сих пор пуст.
6. **Версия релиза и исходники:** после полного аудита определить релизный коммит, проверить `main`, приложить исходники соответствующей версии и уведомления; отдельно подтвердить Authenticode обоих EXE. Существующие неподписанные архивы нельзя называть одобренными SignPath.

## Как проверить результаты

1. Открыть GitHub Actions PR №1 → `DeiLaw Windows candidate (unsigned)`; успешное выполнение текущего HEAD должно показывать новую проверку и unit-тесты.
2. Скачать **только как тестовый артефакт** `Deilaw-unsigned-candidate`; изучить `license_evidence.json`, список `priority_packages_without_original_notice` и `windows_binaries`. Не интерпретировать `technical_integrity_ok=true` как `legal_compliance=true`.
3. Проверить каждый реальный бинарный модуль и документировать принятые решения в `docs/THIRD_PARTY_COMPLIANCE_0.3.1.md`; после ручной проверки провести инсталляционные испытания.
4. Слияние PR и публикацию официального GPL/SignPath-релиза разрешать только после закрытия всех блокирующих пунктов и отдельного решения правообладателя.

См. также `SIGNPATH_FINAL_GATE.md`, `THIRD_PARTY_COMPLIANCE_0.3.1.md`, `ASSET_RIGHTS_REGISTER.md`, `LICENSE_SCOPE.md`.
