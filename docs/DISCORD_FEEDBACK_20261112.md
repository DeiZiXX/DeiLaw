# Discord-привязка отзывов и репортов — DeiLaw 0.3.5rc7

## Что меняется

- Пользователь может продолжать пользоваться DeiLaw как гость, но **создание новых отзывов и репортов** требует входа через Discord.
- В форме отзыва нет поля ручного ввода ника. Имя показано из Discord-профиля. **Сервер сам получает авторитетные имя и provider_id из `auth.identities`**, не доверяя клиентскому полю или JWT `user_metadata`.
- Каждый Discord-аккаунт может иметь один отзыв. Повторная отправка редактирует старый. Изменение рейтинга/текста снова отправляет отзыв на модерацию, в том числе для администратора.
- Репорты привязаны к `owner_uid` Supabase Auth, поэтому после входа через тот же Discord доступны на другом устройстве; в Support Center 0.2.3 показываются Discord-ник и Discord ID автора.
- Старые записи без Discord ID сохранены. Прежний RPC для подтверждения права на старые репорты продолжает работать по секрету установки.
- Публичные отзывы показывают только ник, оценку, текст и безопасные метаданные; Discord ID отзыва недоступен через общедоступный API.
- Предложения (идеи) пока оставлены без изменений; их форма и авторизация — отдельная следующая доработка.

## Продакшен Supabase

Для проекта `ntizjwncrbokebjsfwgu` **уже применена** миграция `deilaw_discord_identity_reviews_reports_20261112` и две дополнительные правки для модерации/обновления собственной записи админа. **Не запускайте SQL заново** на этом проекте; файл `SUPABASE_DISCORD_FEEDBACK_BINDING_20261112.sql` приведён для переноса на новый проект и аудита.

Проверки после миграции:

- Гостевой `INSERT` в `reviews` и `bug_reports` отклоняется.
- Discord-пользователь может редактировать собственный отзыв, и опубликованный отзыв становится неопубликованным после изменения текста.
- Discord-репорт получает проверенные `owner_uid`, `discord_name`, `discord_user_id`.
- Тестовые операции проводились в `BEGIN ... ROLLBACK`; реальные отзывы и репорты не менялись.
- Прямой SELECT `reviews.discord_user_id` обычным `authenticated` запрещён; внутренний `deilaw_internal` недоступен ролям `anon`/`authenticated`.

## Windows-проверка

1. Соберите `build_app_only.bat`, откройте DeiLaw и войдите через Discord.
2. Откройте «Отзывы»: текстовый ник должен быть заменён на метку «Ваш Discord: ...».
3. Отправьте тестовый отзыв. Он должен попасть в админку как скрытый до одобрения. Повторно отредактируйте: он должен снова ожидать проверки.
4. Отправьте репорт с вложением и откройте его после перезапуска.
5. Запустите Support Center 0.2.3 и проверьте Discord-имя/ID в карточке нового репорта.
6. В гостевом режиме попробуйте отправить отзыв/репорт: должен появиться выбор перейти ко входу Discord.

## Ограничения

GUI/Windows сборки требуют реального тестирования. Не создавайте новую авторизацию вне Discord для отправки отзыва/репорта. Discord ID является персональным идентификатором: его можно видеть в приватной админке репортов, но не публиковать в публичных отзывах.
