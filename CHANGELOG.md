# Changelog

Текущая версия приложения: **0.3.1**. Записи ниже сохраняют исторические номера промежуточных сборок.

## 0.3.5rc10 — подписанные обновления и режимы установки

- Добавлены режимы «Автоматически», «Спрашивать перед установкой», «Только уведомлять».
- Режим хранится в `data/settings.json` и применяется при старте и периодической проверке.
- Включение автоматической установки требует проверенной Ed25519 подписи манифеста, корректного SHA-256 и официального Inno Setup инсталлятора.
- Проверка подписи и хеша повторяется непосредственно перед запуском установщика.
- Неподписанные и портативные сборки не устанавливают обновления автоматически.
- Добавлены тесты выбора режима и проверки подписи.


## 0.3.5rc6 — подготовка JWT/RLS cutover (исходники для Windows-сборки)

- Статус «Гостевой режим» / «Discord: имя» теперь одна компактная кнопка:
  гость может войти через Discord, а Discord-пользователь — сменить аккаунт
  через новый OAuth или выйти с возвратом к выбору входа без диалога о трее.
- Исправлен Windows-сценарий `build_app_only.bat`: он не зависит от разрешения запуска PowerShell-скриптов.
- Клиент Community запрашивает собственные данные по подтверждённому Supabase `owner_uid`.
- Вложения репортов используют JWT и проверку владельца на сервере.
- Подготовлена миграция RLS с защищённым переносом старых отзывов/репортов.
- Промежуточный защитный триггер модерации отзывов уже применён на рабочем Supabase.
- До полной миграции создана приватная резервная копия в Supabase; внешняя копия ещё нужна.
- **Полный JWT/RLS cutover ещё не применён**: требуется собранная Windows-версия и согласованный выпуск.
- Самостоятельная автоматическая установка обновления отключена до подписи установщика.

## 0.3.5rc5 — Кликабельная учётная запись и выход

- Имя Discord и надпись гостевого аккаунта открывают меню с кнопкой «Выйти».
- При выходе DeiLaw удаляет активную локальную сессию, отзывает её на Supabase
  и снова показывает выбор Discord или гостевого входа.
- Остальные сохранённые аккаунты не удаляются; для гостя есть предупреждение.

## 0.3.5rc4 — Автоматический вход (тестовые исходники)

- Последняя Discord- или гостевая сессия восстанавливается автоматически при запуске.
- Просроченный токен обновляется; при ошибке вновь предлагается выбор входа.
- Кнопка «Сменить аккаунт» в боковом меню включает выбор при следующем запуске.
- Добавлены тесты восстановления сессии и смены аккаунта.

## 0.3.5rc3 — Discord + гостевой вход (исходники, не релиз)

- При запуске предлагается вход через Discord или продолжение как гость.
- Discord OAuth через браузер, одноразовый PKCE-код и локальный callback в Windows.
- Гостевая и Discord-сессии хранятся раздельно под защитой Windows DPAPI.
- Cloud AI и Community используют JWT выбранного аккаунта; без выбора входа основное окно не открывается.
- Подготовлены проверки OAuth/переключения и инструкция `docs/DISCORD_AUTH_SETUP.md`.
- Требуется Discord Application, включение провайдера в Supabase и тестирование на Windows.

## 0.3.5rc2 — предварительный патч безопасности (не развёрнут)

- Cloud AI: проверка JWT, серверный поиск норм с источниками и двухуровневая квота.
- Миграция RLS: владение по auth.uid(), защищённый перенос старых репортов и сокрытие приватных столбцов.
- Подготовлен перевод политик RLS предложений на проверенную сессию пользователя.
- Отзывы отправляются на модерацию; защищены административные поля.
- DPAPI для секретов Windows; исключение identity из бэкапов и Git.
- Ed25519-проверка манифеста; автозапуск установщика отключён до безопасного подписанного релиза.
- Безопасный DOCX, ручное включение отправки логов, LIKE и стабильный каталог data/.
- Исходники трёх серверных функций и порядок развёртывания: docs/SECURITY_ROLLOUT.md.
- Требуется синхронное обновление Supabase; пока серверные исправления не применены.

## 0.3.5rc1 — тест биндера в RMRP

- Игровой ввод RP-команд теперь отправляет символы с задержкой, а не одним мгновенным пакетом.
- Клавиши открытия чата и Enter используют scan-коды с удержанием для лучшей совместимости с игровым вводом.
- Минимальная пауза открытия чата увеличена до 250 мс.
- В разделе RP-биндов показывается последняя попытка: получена ли горячая клавиша и принял ли Windows отправленные события.
- По результатам тестирования в RMRP увеличена пауза перед Enter и время его удержания; добавлена необязательная опция «Закрывать чат Esc» для клиентов, где чат остаётся открытым после отправки.
- Подтверждение работоспособности внутри RMRP требует тестирования на Windows с запущенной игрой.
